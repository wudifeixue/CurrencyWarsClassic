# 货币战争 · 经典回响

以《崩坏：星穹铁道》旧赛季「货币战争·零和博弈」为参考的非官方浏览器策略小游戏。刷商店、招募角色、追求升星、组合装备、选择投资策略，再用前后台阵容完成一场 12 关远征。

[直接试玩](https://wudifeixue.github.io/CurrencyWarsClassic/) · [源码仓库](https://github.com/wudifeixue/CurrencyWarsClassic)

**网站 v4 已改用经典卡池、费用、羁绊资料及常规装备合成表，并补充实际战斗触发效果。** 当前包含 72 名经典可招募角色、33 项原版羁绊资料、44 件常规装备、36 个合成配方、33 项可选投资策略。另保留 5 名早期网页角色用于读取旧存档，内部共有 77 名角色；这 5 名角色不会进入新局商店。

战斗是基于速度的二维自动回合模拟。技能、治疗、护盾、持续伤害、弱点击破、追加攻击和装备被动参与逐次结算；胜负取决于实际战况，阵容估值仅供参考。它是一款有明确简化范围的独立改编，不是原游戏的完整复刻或强度计算器。

资料范围为 **4.7「入画奇航」改版之前的「零和博弈」**，包含旧赛季后续扩展角色，并非只冻结在 3.7 首发。装备保留已核实的 3.8 平衡加强；投资策略采用包含 4.4 扩展、更新于 2026-08-30 的可追溯资料快照。新赛季资料没有混入卡池，无法确认引入版本的数值差异也没有直接覆盖旧值。

## 怎么玩

1. 在上方五格商店招募角色。拖动头像，或点击角色详情中的移动按钮，把角色安排到前台、后台或备战席。
2. 查看角色右上角的前后台标记，按赋能位置部署。放在其他区域不会禁止摆放，但不会激活对应的角色赋能；备战席角色不参加战斗，也不计入上场羁绊。
3. 三张同星同角色自动合成为更高星级，最高三星。升星优先保留已部署角色，不相容或超出栏位的装备会退回仓库。
4. 在装备仓库穿戴装备，在装备工坊合成。通常每人最多三件；唯一装备不能在同一角色上重复穿戴，「随便骰子」需要三个空栏位并占用其余两栏。装备可以免费卸下，出售角色也会返还装备。
5. 第 2、6、10 关选择投资策略，其他补给节点选择装备。根据羁绊和阵容，在刷新、升星、升级与存钱吃利息之间取舍。
6. 点击「出战」，观看自动战斗与结算，再继续下一关。第 4、8、12 关是首领节点；完成最后一战结束远征。

前台最多 4 人，前后台合计人数不能超过当前团队等级，最高 10 级；备战席为 9 格。可见的空槽不代表当前已经拥有相同数量的上场名额。

### 经济与策略

普通刷新消耗 2 金币，免费刷新次数会优先使用。购买经验消耗 4 金币、获得 4 经验；本作升级所需经验为适配 12 关而设置的试用数值。商店五档费用概率随等级变化，显示值与实际抽取共用旧赛季概率表。

通常每持有 10 金币获得 1 利息，最多 5。策略可以改变经济方式：例如「利息上调」将上限提高到 10；「买断制」取消利息、改为每个新节点获得经验；「淘金客」只奖励花费金币的刷新；「武力刷新」在成功合成装备时提供免费刷新。「孪生素数」对每档费用只奖励第一次购买，读取存档不会重复领取。

锁定商店可保留下个节点的卡牌。战斗收入、连胜或连败奖励及小队生命扣除沿用本作的 12 关规则，不能视为原版经济曲线。

## 回合制战斗

战前构筑决定自动行动策略与触发条件。前台承担敌方攻击，后台依据赋能主动行动或响应事件；后台不会直接承受敌方常规攻击。速度、行动提前与延后会改变出手顺序，前台共享战技点，技能、羁绊和装备可以改变其上限与恢复方式。

不同搭配会改变实际事件。例如，桑博施加并引爆风化，卡芙卡提前引爆持续伤害；三月七在后台提供护盾，黑塔在敌人生命越过阈值时追击；「掩体生成枪」按回合为前台加盾，「蓄能帆」按经过的行动值回能，「火力风暴潮」随攻击累积强度。这些效果不是只折算成一个总战力数值。

护盾先吸收伤害，治疗按实际损失的生命恢复。匹配弱点的攻击削减敌方韧性，击破触发附加伤害与行动延后。敌方全灭则获胜；前台全灭或达到行动上限仍未清除敌方则失败。角色单场损失的生命不会带到下一场，战败另行扣除远征小队生命。

战斗回放提供暂停、单步、1× / 2× / 4× 速度与跳过功能。结算可切换阵容总览和实际伤害柱状图，并回看最近一场战斗。回放控制不会改变已经计算好的结果。伤害统计包含对护盾造成的伤害，治疗统计使用实际恢复量。

## 横版界面

界面按照玩家提供的实机截图重绘：蓝紫色竞技场、顶部悬浮商店、中央方形角色卡、底部备战席、左侧羁绊、右侧装备，以及投资选卡和黑金结算页面。采用 **1920 × 1080 的 16:9 画布**，随窗口整体缩放；桌面与横屏设备更适合操作，竖屏可使用放大功能。

v4 修复了角色移入备战席后头像变黑，以及人口数字旁图标错位的问题。备战席头像保持正常显示，人口标记与角色前后台赋能标记分别呈现。商店可以收起，装备与羁绊使用已取得的原版图标，并保留本地备用图形。

快捷键：`D` / `R` 刷新商店，`F` / `E` 购买经验，空格出战或暂停回放，`→` 单步回放，`?` 打开玩法指南。

## 存档兼容

进度自动保存在当前浏览器的 `localStorage`。重新访问同一网址可继续；本地地址与 GitHub Pages、不同浏览器或不同设备之间不会自动同步。清除网站数据会删除进度。

网站早期版本使用的存档结构 v1 会自动迁移到结构 v2，已有金币、角色、装备、关卡、策略和战报继续保留。旧存档中的非经典角色与早期自制策略保留兼容行为，但不进入新局随机池。装备 ID 保留，名称、配方和效果更新为经典规则；原先允许的重复唯一装备或骰子栏位冲突会整理并返还仓库，不会直接丢弃物品。

迁移不会重发策略奖励。有逐次事件的旧战报可以继续回看；最早没有回放数据的战报不能补生成历史过程。网站版本号与存档结构版本号是不同概念。

## 本地运行与测试

需要 Python 3。在仓库根目录运行：

```sh
python3 -m http.server 4173 --directory dist
```

打开 [http://localhost:4173](http://localhost:4173)，或使用 `npm start` 启动相同服务。页面使用 JavaScript 模块，需要通过 HTTP 服务访问。

使用 Node.js 22 或更新版本运行测试：

```sh
node --test tests/*.test.mjs
```

也可以运行 `npm test`。测试覆盖合成配方、升星与装备返还、经济策略、商店概率、人口限制、存档迁移、回合战斗及界面数据。项目没有需要 `npm install` 的运行依赖，也没有额外构建步骤；`dist/` 就是可部署的网站。

## GitHub Pages 发布

仓库 **Settings → Pages → Build and deployment → Source** 使用 **GitHub Actions**。推送到 `main` 或手动运行 `Deploy to GitHub Pages` 工作流后，先执行规则测试，通过后上传 `dist/` 并部署。工作流发布静态文件，不需要应用服务器或额外部署密钥。
